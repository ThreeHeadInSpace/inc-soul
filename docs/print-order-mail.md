# Проверка почты для заказов

Команда разработчика отправляет тестовый заказ с готовыми PNG или JPEG через Яндекс SMTP. Используйте синтетические фотографии. Для S3 можно взять PNG, скачанный кнопкой «Скачать PNG для печати». Полный ID фотоленты находится в имени файла и в подсказке к короткому номеру.

Укажите в локальном игнорируемом `.env` или в окружении процесса `SMTP_HOST=smtp.yandex.ru`, `SMTP_PORT=465`, `SMTP_USER`, `SMTP_PASSWORD` (пароль приложения Яндекса) и `PRINT_ORDERS_TO_EMAIL`. Отправителем будет `SMTP_USER`. Команда использует TLS.

Сохраните манифест рядом с изображениями в закрытом рабочем каталоге. Укажите тестовый номер в формате `000-001`. Для нового теста создайте новый служебный UUID через `node -e "console.log(crypto.randomUUID())"`.

```json
{
  "orderId": "4f34d8dd-9277-4e90-811a-2207f293f078",
  "orderNumber": "000-001",
  "createdAt": "2026-11-03T21:55:00Z",
  "totalRub": 989,
  "strips": [
    { "stripId": "465721a5-2cca-499d-a8c3-5cae28b164f8", "file": "strip-1.png", "product": "Ленточка 3 фото", "copies": 2 },
    { "stripId": "f7efc481-ad06-423d-9006-91421fa336b0", "file": "strip-2.png", "product": "Ленточка 3 фото", "copies": 3 }
  ]
}
```

```sh
npm run print:test-mail -- artifacts/print-mail/order.json
```

Дата в письме переводится в московское время. Метки A001, A002 и далее действуют внутри заказа и совпадают с метками в именах вложений. Файлы прикладываются байт в байт. В манифесте можно добавить `customerName`, `phone` и `address`. Скрипт ждёт ответа SMTP и создаёт файл `<orderId>.smtp-status` рядом с манифестом. Строка `accepted` означает, что SMTP принял письмо. Повтор с тем же ID в том же каталоге блокируется. Если есть только `attempted`, сначала проверьте почту: сбой мог произойти после приёма письма. После ошибки проверки сети или пароля до попытки отправки можно сразу повторить команду.

## Production

Для сохранения связей заказов с фотолентами примените миграции к постоянной Postgres через штатный `npm run db:migrate` с настроенным `DATABASE_URL`. Текущая форма оформляет одну фотоленту с выбранным числом копий. Серверный формат заказа поддерживает дополнительные фотоленты с отдельным количеством копий. Новые номера выдаёт общий счётчик Postgres. Ранее выданные номера сохраняются.

Для коммерческого запуска нужны серверная интеграция оплаты, сохранение полноразмерных файлов печати на ограниченный срок и долговечный статус отправки с повторными попытками. Обработчик должен проверять платёж на сервере, атомарно резервировать отправку и дожидаться `sendMail()` на сервере. Настройте переменные SMTP только в серверном окружении Vercel и проверьте подключение из него. Локальная команда предназначена для пробной отправки.
