# Гостевая корзина печати

Рабочий сценарий включается на Vercel Preview с прежним PRINT_PREVIEW_ACCESS_CODE.
Новых переменных окружения нет. Публичный сбор персональных данных по-прежнему
требует действующей политики конфиденциальности. Для Preview используйте
тестовые фотографии и вымышленные контакты.

Новые оригиналы сохраняются в IndexedDB incsoul-print. В assets хранится один
готовый PNG 600×1800 с плотностью 300 DPI, в info сведения о пригодности.
Недавние снимки сохраняют небольшие JPEG-превью прежним механизмом.
Идентификатор готовой версии зависит от содержимого PNG. Изменение фильтра или
подписи создаёт отдельную версию. Исходные снимки не перезаписываются.
Картинки с недостаточным разрешением кадров доступны для цифрового скачивания,
а их печать заблокирована.

Старые недавние снимки сохраняются. Если JPEG действительно имеет разрешение
не менее 600×1800 и пропорции фотоленты, он может быть принят как исходник
печатного PNG. Миниатюры нельзя заказать. Увеличения разрешения нет.

Корзина хранится в IndexedDB отдельно от недавних. Количество меняет только
число в записи, оригинал остаётся прежним. Удаление недавнего снимка освобождает
оригинал только при отсутствии позиции в корзине. Изменения между вкладками
передаются BroadcastChannel, записи выполняются транзакциями IndexedDB.
Общий локальный объём оригиналов ограничен 150 МиБ. Сохранение не обещает
синхронизации устройств или защиты от явной очистки данных браузера.

Технические пределы находятся в src/lib/cart-limits.ts. До утверждения
бизнес-лимита в Preview допускаются 4 позиции, 12 экземпляров позиции,
24 экземпляра всего, 3,3 МБ одного PNG и 9 МБ суммарно.
Это позволяет передавать каждый PNG отдельным запросом Vercel и удерживать
письмо с MIME-вложениями в пределах существующего SMTP-механизма.
Сервер самостоятельно проверяет состав, количества, размеры и содержимое PNG,
включая CRC и распаковку пикселей.

Миграция 0007_group_print_orders.sql добавляет print_uploads и print_order_items,
а также счётчик загрузок в print_order_limits. Старые заказы и print_png остаются
доступными. API одиночного заказа использует ту же регистрацию группового заказа.
Создание родительской записи и всех позиций выполняется одной SQL-операцией.
PNG позиций хранятся в приватных bytea, RLS включён, доступ Data API отозван.
Успех возвращается только после сохранения всех файлов. Владелец получает PNG
во вложениях SMTP с номером заказа, ID фотоленты и количеством в тексте письма.

Загрузки до подтверждения ограничены по частоте. Временные файлы удаляются
после регистрации заказа. Брошенные загрузки старше суток очищаются при
следующей загрузке. При отсутствии последующих загрузок очистка откладывается.
Для непрерывной фоновой очистки можно отдельно настроить расписание PostgreSQL.

Перед отправкой браузер сохраняет UUID запроса и снимок состава в IndexedDB.
После неопределённого ответа состав блокируется до проверки или повторного
оформления с тем же UUID. При перезагрузке нужно повторно ввести контакты и код,
поскольку адрес и код не записываются на диск. Корзина очищается только после
подтверждения сервером. Ошибка SMTP сохраняет заказ, статус уведомления и файлы.
Для повторной отправки владельцем остаётся scripts/retry-free-print-mail.mjs.
